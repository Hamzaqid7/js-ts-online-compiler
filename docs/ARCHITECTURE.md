# Architecture

This document explains how the JS/TS Online Compiler works internally. The whole application lives in a single file, `index.html`, organised as: head (theme bootstrap, CSS), markup, and three `<script>` blocks.

## High-level overview

```
┌─────────────────────────────── index.html ───────────────────────────────┐
│                                                                          │
│  Header (language, font size, examples, open, save, theme, run/stop)     │
│                                                                          │
│  ┌── Editor pane ──────────┐  ┃  ┌── Output pane ───────────────┐        │
│  │ tabs · Ln/Col · tools   │  ┃  │ <pre id="out"> log lines     │        │
│  │ gutter │ <pre> highlight│  ┃  └──────────────────────────────┘        │
│  │        │ <textarea>     │  ┃ resizable divider                        │
│  └─────────────────────────┘                                             │
│                                                                          │
│  Footer · Toast · hidden #iw (iframe host) · canvas background           │
└──────────────────────────────────────────────────────────────────────────┘
                    │ Run
                    ▼
   (TS only) ts.transpileModule ──► JS ──► sandboxed <iframe srcdoc>
                                                  │ console / errors
                                                  ▼
                                        window.postMessage ──► Output pane
```

## Page load sequence

1. **Theme bootstrap (inline, in `<head>`)** reads `localStorage.theme`, defaults to `dark`, and sets `data-theme` and `data-bs-theme` on `<html>` *before* first paint to avoid a flash.
2. **Loader overlay** (`#loader`) shows a boot log and progress bar. It finishes when the window `load` event fires (minimum ~1.8 s, maximum 9 s; ~0.3 s with reduced motion). If `window.ts` is missing it shows "TypeScript compiler unavailable".
3. **Canvas background script** draws the animated grid (see below).
4. The **TypeScript compiler** is loaded from cdnjs (`typescript@5.4.5`).
5. The **main script** reveals `#app-container`, restores saved state and wires up all event handlers.

## The editor

The editor is a hand-built overlay, not a library such as CodeMirror or Monaco:

| Layer | Element | Role |
| --- | --- | --- |
| Gutter | `#ln` / `#lni` | Line numbers; scrolled in sync via `translateY` |
| Current line | `#cl` | Highlight bar positioned from the cursor's line index (CSS variable `--cl`) |
| Highlight | `#hl` (`<pre>`) | Colored token HTML generated by `hl()` |
| Input | `#code` (`<textarea>`) | Transparent text on top; handles all real typing and selection |

- **Syntax highlighting** (`hl()`): HTML-escapes the source and runs a single combined regular expression with capture groups for comments, strings/template literals, numbers, keywords, and other token classes, wrapping matches in classed `<span>`s. Colors come from CSS variables (`--kw`, `--st`, `--nm`, …) so they follow the theme.
- **Editing helpers** use `document.execCommand("insertText")` rather than assigning `textarea.value`. This keeps the browser's native **undo/redo** stack intact. `editLines()` rewrites only the lines touched by the selection and is used for indent, outdent and comment toggling.
- **Keydown handler** implements Tab, `Ctrl/Cmd+Enter` (run), `Ctrl/Cmd+/` (comment), `Ctrl/Cmd+S` (save), smart Enter (auto-indent) and auto-closing pairs.
- **`pos()`** updates `Ln / Col` and selection size and the active-line highlight.

## State model

```js
let lang = "js";                       // active language
const tabs = [{ id: "main", name: "main.js", lang: "js" }];
let active = "main";                   // active tab id
let kill = null;                       // cleanup fn for the running iframe
```

- The **main tab** persists to `localStorage` as `c_js` / `c_ts` (one per language) on every input.
- **Extra tabs** (from **Open**) store their text in `tab.content` in memory only, plus cursor and scroll position (`s`, `e`, `sc`) so switching tabs feels seamless.
- `activate(id)` saves the current tab's state, swaps the textarea contents and restores the cursor/scroll of the target tab.

## Execution pipeline (`run()`)

1. Disable **Run** and clear output.
2. **If TypeScript:** call `ts.transpileModule(source, { reportDiagnostics: true, compilerOptions: { target: ES2020, module: ESNext } })`. Any diagnostics are printed as `file(line,col): message` and execution is aborted. Otherwise use `outputText`.
3. Escape any `</script` sequence in the code so it can't terminate the wrapper tag.
4. Build an HTML document string:
   ```html
   <!DOCTYPE html><html><body>
     <script>(boot)()</script>
     <script type="module">…user code…</script>
   </body></html>
   ```
   `boot` is the **function's own source** (`boot.toString()`), injected so it runs inside the iframe.
5. Create `<iframe sandbox="allow-scripts allow-modals">`, set `srcdoc`, and append it to the hidden `#iw` container.
6. Register a `message` listener that only accepts events whose `source` is this iframe's `contentWindow`, and appends them to the output.

### Inside the iframe — `boot()`

`boot()` is the bridge between user code and the host page:

- Overrides `console.log/info/warn/error/debug` to format arguments (handling strings, functions, `BigInt`, `Symbol`, circular references via `WeakSet`) and `parent.postMessage({ t, m }, "*")`.
- Maps `console.table` to a log of the data and `console.clear` to `{ t: "clear" }`.
- Wraps `prompt` (native dialog, then logs the question and answer), `alert` (logs) and `confirm` (logs, returns `true`).
- Adds `error` and `unhandledrejection` listeners that report to the parent.

### Stopping

`kill()` removes the `message` listener and the iframe element, ending the sandboxed script's ability to report output. **Stop** and **Clear** both call it.

## Security model

- `sandbox="allow-scripts allow-modals"` **without** `allow-same-origin` gives the iframe an opaque origin. User code cannot read the host's `localStorage`, cookies or DOM.
- Messages are filtered by `event.source`, so other windows can't inject output.
- User code *can* perform network requests and open modal dialogs, as any web page can.
- The host never `eval`s user code; it is executed by the browser inside the iframe.

## Theming

Design tokens are CSS custom properties on `:root` (`--bg`, `--pn`, `--tx`, `--ac`, `--kw`, …). Three layers define them:

1. Light defaults
2. `@media (prefers-color-scheme: dark)` for `:root:not([data-theme="light"])`
3. Explicit `:root[data-theme="dark"]`

`setTheme()` updates `data-theme` and `data-bs-theme` (so Bootstrap components follow along) and persists the choice. The canvas background watches `data-theme` mutations to repaint.

## Layout & split pane

`<main>` uses CSS grid with a CSS variable `--lr` representing the left pane's share of the width. The divider supports pointer drag (with pointer capture), arrow keys (±24 px) and double-click to reset (removing `--lr`). A minimum pane width of 280 px is enforced.

## Canvas background (`#laserGrid`)

A self-contained IIFE draws a faint blueprint grid with slow "data trace" pulses and a soft pointer spotlight:

- Geometry is cached in `Path2D` objects and rebuilt on resize (`ResizeObserver`).
- Pulse count scales with viewport area (8–16).
- DPR is capped at 1.75 for performance.
- Animation pauses when the tab is hidden and is replaced by a static render when `prefers-reduced-motion` is enabled.

## Known issues & improvement ideas

**Things worth cleaning up**

- The footer reads *"Engine Ready • Node.js v20.11 / TS 5.4"*, but code runs in the **browser**, not Node. Consider changing it to "Browser runtime / TS 5.4".
- The footer **Documentation** and **GitHub** links currently point to `#`. Update them to `docs/USER_GUIDE.md` (or the Pages URL) and your repository.
- `@import url('Fonts/Consolas.ttf')` is not a valid way to load a font (`@import` expects a stylesheet), so Consolas is never applied and the stack falls back to *Courier New*. Use an `@font-face` rule if you want to ship a font file.
- The header logo links to `index.html`, so the file should be named `index.html` when deployed (the repo already does this).
- A commented-out block disables right-click and DevTools shortcuts. Such blocking is easily bypassed and hurts accessibility; consider deleting it.
- The elapsed-time indicator measures iframe load, not total script duration.

**Feature ideas**

- Real type-checking using a TypeScript language-service worker
- Shareable links (encode code in the URL hash)
- Running the script in a Web Worker with a timeout to guard against infinite loops
- Additional themes and an editor library (CodeMirror / Monaco) for autocomplete
- Export/import of full workspaces (all tabs)
- Unit tests for the formatter and highlighter
